# 飞牛 NAS · 115 独立 ZIP 备份

Web 页面选择 NAS 源目录，通过 OpenList WebDAV 上传到 115。端口 `1124`。

## 新版行为

- 以 **5 GiB ZIP 成品大小**为封包目标：先按照片日期顺序累积文件，生成后若压缩 ZIP 不足 5 GiB 且仍有后续文件，就合并下一批并重打，直到成品达到 5 GiB。文件不拆分；超过 5 GiB 的单个文件独立成包；最后一包不足 5 GiB 时完整封包并显示差额。
- 使用 WinZip AES-256 ZIP 加密和 Deflate 压缩。每包可单独下载，用支持 AES ZIP 的 7-Zip 等软件输入密码解压。某些系统内置解压器不支持 AES ZIP。
- 两次输入密码必须一致；保存时实测加密、正确密码解密、错误密码拒绝。每个实际归档上传前完整解密读取，并逐文件比对 SHA-256。
- 验证能发现输错，不能防止日后遗忘。密码请存入密码管理器。ZIP 文件内容加密，文件名不隐藏；配置文件权限为 600，网页不返回已保存的密码。
- 顺序：EXIF 拍摄/生成日期优先，其次文件系统创建时间，最后修改时间。日志统计日期来源。Linux inode 的 ctime 不作为创建时间；HEIC 等 Pillow 无法读取 EXIF 的格式会回退。
- 首轮从旧到新连续生成独立 ZIP，末包不足 5 GiB 也处理。自动扫描默认每 60 分钟检查，新增和修改累计 1 GiB 后运行；界面可调整扫描间隔和自动触发阈值，阈值 0 表示有变化就备份。
- 首页展示总体扫描/完成进度、当前包的 ZIP 上传字节进度、每日首次发现的新增/变更量、每日确认上传量及近一年热力图。
- 已确认上传成功的 ZIP 会出现在包清单中。勾选删除时会列出具体文件并二次确认，然后删除对应的 115 文件和本地副本；逐包清单可用时同步撤销增量状态。旧版无逐包文件清单的归档要求全选删除，避免留下会跳过重备份的状态。
- **手动备份不受大小门槛限制**。任务可停止，记录可清空；单独清空记录不删除 ZIP 或增量状态。
- 失败保留已验证的 ZIP，重试使用同一文件名。只有 WebDAV 返回成功后才提交该包的文件状态；重启后会继续未完成的首轮。
- 分阶段日志：扫描、压缩加密、完整解密校验、发送至 OpenList、等待 OpenList/115 确认、成功。发送 100% 不是云端成功，等待阶段持续显示耗时。

## Compose 部署

```bash
cd /你的项目目录
docker compose up -d --build
```

本仓库 Compose 按当前 NAS 配置：

| NAS 路径 | 容器路径 | 用途 |
|---|---|---|
| `/vol1/1000/存储空间1/docker/115/config` | `/config` | 密码、任务和增量状态 |
| `/vol1/1000/存储空间1/docker/115/archives` | `/backups` | 新版独立 ZIP |
| `/vol1`、`/vol2`、`/vol3` | `/sources/vol1`、`/sources/vol2`、`/sources/vol3` | 只读目录选择 |
| `/vol3/1000/存储空间3/备份/照片` | `/data/照片` | 原照片路径兼容 |

打开 `http://192.168.5.23:1124`，浏览目录选择来源，填写 WebDAV 目标，输入两次 ZIP 密码并保存验证，再启动备份。换 NAS 请修改 Compose 路径。页面应仅供可信局域网访问。

旧 `.tar.gz.enc.part*` 不会被转换或删除。升级首次运行禁用旧定时、要求重新验证 ZIP 密码。新版使用独立增量状态，会重新生成照片的 ZIP 全量备份；旧清单不会让照片被漏备份。

## 恢复

1. 单包恢复：下载任意完整 `.zip`，使用支持 AES ZIP 的软件输入创建该包时的密码，解压到空目录。无需其他包，也无需拼接。
2. 全部恢复：收集全部成功的 ZIP，按文件名的生成时间从旧到新逐包解压到同一个空目录；遇到同路径文件以新版本覆盖旧版本。每个包只含该批文件，并不代表整库全量。
3. 首轮全量未完成时，只有已成功生成的批次可恢复；页面首轮成功后才覆盖首次扫描到的全部文件。
4. 此版本不传播源文件删除，也不是时间点快照。备份期间源文件发生变化会报错并保留未提交状态，下次重新扫描。
5. 更换密码只影响后续新包，旧包需要旧密码。

保留 `/config` 以便增量续传；它并不是单个 ZIP 解压的必要条件。所有包仍应做一次异地下载恢复抽查。
